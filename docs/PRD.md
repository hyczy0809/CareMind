# CareMind PRD v0.4

版本：v0.4 Gemma 4 capability-aligned
日期：2026-06-12
产品定位：面向失智症家庭照护者的家庭照护整理与复诊沟通工具
核心边界：CareMind 帮助记录、整理、提醒和沟通，不提供诊断、处方、检查决策或急救服务。

## 1. 背景与目标

CareMind 面向失智症家庭照护中的长期断点：

- 家属每天经历大量碎片化照护事件，但难以持续记录。
- 睡眠、饮食、服药、安全和行为变化散落在聊天和记忆中。
- 复诊时，家属很难把近 7 天或近 30 天变化讲清楚。
- 面对“有人偷钱”“我要回家”“拒绝吃饭/服药”等场景，家属缺少低冲突回应方式。
- 长期照护压力集中在家属身上，但传统工具往往只记录患者，不记录照护者。

MVP 目标：

1. 用户可以在 30 秒内完成一条照护记录。
2. 系统可以结构化睡眠、行为、服药、饮食、安全和照护者状态。
3. 系统可以生成“今天值得关注”的非诊断性提醒和今晚行动建议。
4. 系统可以生成可直接使用的低冲突沟通话术。
5. 系统可以生成近 7 天/30 天复诊摘要、医生问题清单和资料清单。
6. 用户可以上传或手动补充复诊资料，经家属确认后进入摘要和 PDF。
7. 系统可以提供低风险、非医疗性质的今日陪伴活动，并记录反馈。
8. 今日照护同类关注事项只展示一条，避免重复卡片增加负担。
9. 系统默认采用“端侧 Gemma 4 E2B/E4B + 云侧 Gemma 4 26B/31B”的能力分层，轻量任务优先本地处理，长上下文和多模态任务使用云侧模型。

## 2. 核心场景

| 场景 | 用户任务 | 系统输出 |
|---|---|---|
| 日常照护记录 | 快速记录今天发生了什么 | 结构化日志、今日关注事项、行动建议 |
| 沟通话术 | 面对患者反复表达时知道怎么说 | 不建议说法、可以试着说、背后原则 |
| 复诊准备 | 整理近 7 天/30 天情况 | 摘要、医生问题、资料清单、PDF |
| 照护者支持 | 识别自己是否快撑不住 | 四维 check-in、减负建议、危机提示 |
| 今日陪伴 | 安排低压力陪伴活动 | 活动建议、停止条件、反馈记录 |
| 复诊资料补充 | 上传或补充病历/检查/用药资料 | 非诊断整理草稿、家属确认、摘要聚合 |

## 4. 关键规则

### 今日关注事项

- 每条关注事项带有稳定的 `type` 或 `attention_dedupe_key`。
- 今日照护页同一类型只展示一张卡片。
- 严重度更高优先；严重度相同时保留更新时间最新的一条。
- 历史重复记录仍保存在日志和复诊摘要数据中。

### 复诊资料

1. 支持 PDF/JPG/PNG/DOCX 上传，也支持无文件手动补充。
2. 系统使用 Gemma 4 多模态生成非诊断整理草稿，只提取资料类型、日期、标题、1-3 条复诊沟通要点和术语解释候选。
3. 草稿必须由用户确认后变为 `reviewed`。
4. 只有 `reviewed` 资料会进入后端摘要、资料清单和 PDF。
5. 模糊、缺页或扫描质量差时必须标注“无法可靠读取”，不得猜测报告内容。
6. 用户可删除资料；删除后从本地资料池和 PDF 输出中移除。

### Gemma 4 能力分层

| Intent | 默认模型 | fallback |
|---|---|---|
| daily_log | 端侧 E4B | 超过 4s、失败或低置信字段过多时转云侧 26B |
| communication | 端侧 E2B/E4B 处理短句；云侧 26B/31B 处理复杂关系 | 端侧失败时云侧生成 |
| follow_up | 云侧 26B/31B | 云侧失败时本地摘要兜底并标注来源 |
| followup_document | 云侧 26B/31B 多模态 | 解析失败时手动补充 |
| medical_boundary/crisis | 端侧检测 + 规则兜底 | 复杂解释和求助信息由云侧生成 |

日志结构化必须返回完整 JSON，字段缺失为 `null`，每个字段带 `confidence`；`confidence <= 0.6` 进入 `low_confidence_fields`。疑似诊断、病程判断或用药建议统一标记 `diagnostic_risk: true`，默认不进入摘要或 Memory。

复诊摘要默认使用云侧 Gemma 4 26B/31B，输入包括选定时间窗内的照护记录、daily metrics、已确认资料文本/关键截图和照护者趋势。输出 600-800 字，使用“家属记录/观察到/描述”为主语，不使用“病情”“诊断”等医疗定性词。

### 本地处理优先

开启后，轻量日志、简易话术、基础越界/危机检测优先端侧完成；多模态文件默认只在本地保存和本地解析，端侧无法可靠整理时可手动补充或单次授权云侧整理。需要云侧复诊摘要或文件整理时，必须说明上传范围并获得用户确认。分析埋点不上传原始照护文本。

### Safety

CareMind 不回答：

- 诊断请求。
- 药物调整请求。
- 检查决策请求。
- 自伤/伤人/走失/无法保证安全等危机场景中的普通建议。

系统必须把越界请求转成可执行替代任务，例如整理近期变化、加入复诊问题、记录观察事实或生成给医生的一段话。

## 5. 验收标准

| 编号 | 验收项 | 标准 |
|---|---|---|
| AC-01 | 用户可输入自然语言照护记录 | 输入 1-1000 字后可点击“帮我整理” |
| AC-02 | 系统可生成结构化日志 | 至少覆盖睡眠、行为、饮食、照护者状态 |
| AC-03 | 用户可保存日志 | 保存后写入日志、事件和指标 |
| AC-04 | 系统可生成今日关注事项 | 包含观察依据、行动建议、边界说明 |
| AC-05 | 系统可生成沟通话术 | 包含不建议、可以试着说、原则和记录建议 |
| AC-06 | 系统可生成复诊摘要 | 支持早期摘要、近 7 天和近 30 天 |
| AC-07 | 系统可生成可复制复诊摘要 | 摘要包含核心变化、问题清单、资料清单和医疗边界说明，可一键复制 |
| AC-08 | 今日关注事项去重 | 连续保存两条同类饮食/饮水记录后，首页只出现一张同类关注卡 |
| AC-09 | 今日陪伴可反馈 | 用户可对陪伴活动标记完成/跳过并记录反应 |
| AC-10 | 复诊资料可上传 | PDF/JPG/PNG/DOCX 文件可上传并生成资料记录 |
| AC-11 | 复诊资料可手动补充 | 无文件时可填写类型、标题、摘要并保存 |
| AC-12 | 资料整理草稿需确认 | 未确认资料不进入复诊摘要，确认后进入 |
| AC-13 | 后端摘要可聚合资料 | reviewed 资料进入后端摘要和资料清单 |
| AC-14 | 后端摘要失败可兜底 | 接口失败时页面展示本地摘要并可生成可复制摘要 |
| AC-15 | 医疗边界可拦截 | 诊断、用药、检查决策均转为替代行动 |
| AC-16 | 危机表达可拦截 | 自伤/伤人/走失等触发紧急支持卡 |
| AC-17 | Gemma 4 分层路由生效 | daily_log 端侧优先，follow_up 和 followup_document 云侧优先，fallback 可记录 |
| AC-18 | 多模态资料不可读不猜测 | 模糊或缺页资料展示“无法可靠读取”，并提供手动补充 |
| AC-19 | 本地处理优先模式可用 | 开启后轻量任务优先端侧，云侧处理前展示上传范围确认 |
| AC-20 | 混合语言资料可整理 | 中文记录混合英文术语时，输出中文解释并保留英文原文 |
